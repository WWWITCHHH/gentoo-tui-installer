# Участие в разработке

Спасибо за интерес к проекту. Установщик изменяет диски и работает от root,
поэтому к изменениям предъявляются повышенные требования к предсказуемости,
quoting и тестам.

## Перед началом

```bash
git clone <repository>
cd gentoo_installer
make check
```

Для `make check` нужны Bash 4.4+, GNU coreutils, `shellcheck` и стандартные
утилиты Linux. Root не требуется. Если ShellCheck отсутствует:

```bash
emerge --ask dev-util/shellcheck    # Gentoo
sudo apt-get install shellcheck     # Debian/Ubuntu
```

## Стиль кода

- Bash 4.4+, без зависимостей от Bash 5.
- Отступ — 4 пробела; в `Makefile` — табы.
- Код, имена функций, переменных и комментарии — английские. Строки UI и
  сообщения пользователю — русские.
- Каждый модуль начинается с `# shellcheck shell=bash` и краткого комментария.
- Точка входа и тесты используют `set -Eeuo pipefail`. Библиотечные модули не
  меняют глобальные опции shell.
- Функции имеют префикс области: `disk_`, `stage3_`, `portage_`, `kernel_`,
  `system_`, `tools_`, `bootloader_`, `desktop_`, `finalize_`, `wizard_`, `ui_`.
- Глобальные переменные — `GI_`, `CFG_`, `PLAN_`, `STATE_`, `UI_`.
- Все подстановки переменных — в кавычках: `"$var"`, `"${array[@]}"`.
- Для команд используйте массивы и `ui_run`/`ui_run_input`, а не `eval` и не
  склейку shell-строк.
- Не добавляйте `dialog`, `whiptail`, `jq`, Python и другие зависимости, которых
  может не быть в Minimal CD, без обсуждения.
- Не подавляйте ошибки без причины. Если ошибка нефатальна, логируйте её через
  `warn`/`log_warn` и объясняйте причину.
- Не пишите пароли, токены и содержимое stdin в конфигурацию, state и журналы.

`SC2034` в ShellCheck отключён, потому что часть переменных используется
косвенно. Не отключайте другие проверки без обоснования.

## Изменения конфигурации

Новый ключ требует согласованных изменений:

1. Добавить ключ в `CONFIG_KEYS` (`lib/core.sh`).
2. Добавить значение по умолчанию в `config_defaults`.
3. При необходимости обновить `config_derived`.
4. Добавить валидатор и вызов в `config_validate`.
5. Добавить поле в `conf/installer.conf.example`.
6. Обновить `docs/CONFIGURATION.md` и, если нужно, `docs/HANDBOOK.md`.
7. Добавить тест в `test_core.sh`, `test_validate.sh` или отдельный файл.
8. Убедиться, что `test_config_example.sh` находит ключ и пример загружается.

Не добавляйте ключи для паролей. Пароли запрашиваются интерактивно.

## Тесты

Любое изменение логики должно сопровождаться тестом. Тесты не должны:

- требовать root;
- трогать `/dev/sd*`, `/dev/nvme*` и другие реальные устройства;
- вызывать `parted`, `mkfs`, `mount`, `emerge`, `chroot`;
- зависеть от сети;
- писать вне `GI_TEST_TMP`/`GI_WORKDIR`.

Для функций, вызывающих `die`, используйте `assert_fail_isolated`. Для
проверки побочных эффектов в текущем shell — `assert_ok`/`assert_fail`.
Подробности: [docs/TESTING.md](docs/TESTING.md).

## Коммиты

Используется Conventional Commits:

```text
feat: add Btrfs subvolume selection
fix: clear stale UUID after layout change
test: cover kernel cmdline metacharacters
docs: describe BIOS 2 TiB limit
build: add release archive target
```

Требования:

- один коммит — одна логическая причина изменения;
- сообщение в императиве, на английском;
- в теле объясните «почему», если это не очевидно;
- не смешивайте форматирование и поведение;
- не коммитьте секреты, журналы, `dist/` и временные файлы.

## Pull request

Перед отправкой:

- [ ] `make check` проходит;
- [ ] новые тесты покрывают изменение;
- [ ] обновлены README/docs/CHANGELOG, если затронуто поведение;
- [ ] нет паролей и секретов в коде, тестах и логах;
- [ ] destructive-операции по-прежнему требуют подтверждения;
- [ ] изменение не ломает BIOS/UEFI, OpenRC/systemd и оба варианта `DESKTOP`;
- [ ] для нового оборудования/ядра указано, как проверялось.

В описании PR укажите:

- что и зачем изменено;
- как воспроизвести/проверить;
- какие сценарии из `docs/TESTING.md` пройдены;
- известные ограничения.

## Релиз

1. Обновите `VERSION` (semver) и `CHANGELOG.md`.
2. Убедитесь, что `make check` проходит.
3. Создайте коммит `release: vX.Y.Z`.
4. Поставьте аннотированный тег:

   ```bash
   git tag -a vX.Y.Z -m "Gentoo TUI Installer X.Y.Z"
   ```

5. Соберите архив:

   ```bash
   make dist
   ```

   Скрипт требует чистый worktree и тег, указывающий на `HEAD`. Результат —
   `dist/gentoo-tui-installer-X.Y.Z.tar.gz` и `.sha256`.

6. Приложите архив и контрольную сумму к релизу.
