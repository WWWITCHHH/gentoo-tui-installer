# Changelog

Все заметные изменения проекта. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют
[Semantic Versioning](https://semver.org/lang/ru/).

## [1.4.0] - 2026-10-31

### Добавлено

- Автоматическое определение `VIDEO_CARDS` по PCI vendor/device из sysfs при
  новой установке (`hardware_detect_video_cards`). На странице «Графика»
  значение выбирается из списка (Intel, AMD, NVIDIA open/proprietary, VMware,
  QEMU QXL, virtio, без ускорения) или задаётся вручную.
- Проверка противоречий конфигурации перед установкой
  (`config_check_consistency`): несовпадение профиля и графики, пустой
  `VIDEO_CARDS`, SSH без сети, ручное ядро и отсутствие пользователя при
  выбранной графике. Предупреждения показываются в финальном модальном окне,
  кнопка подтверждения называется «Continue anyway».
- Тесты для серий стрелок и неизвестных escape-последовательностей,
  автоопределения GPU, единственной настройки sudo, предупреждений и пропуска
  desktop-этапа без графики.

### Изменено

- Система инициализации выбирается как OpenRC или systemd; Stage3
  `desktop-openrc`/`desktop-systemd` подставляется автоматически при выборе
  XFCE или GNOME.
- Настройка `Install sudo` осталась только на странице «Пользователи»; дубль со
  страницы «Службы» удалён.
- `VIDEO_CARDS` убран со страницы «Stage3 и сборка»; настройка живёт только на
  странице «Графика» и показывается только при выбранном графическом окружении.
- Стрелки `←`/`→` работают только на панели действий; на содержимом страницы
  они игнорируются.
- Desktop-этап явно пропускается при `DESKTOP=none`; добавлен регрессионный
  тест.

### Исправлено

- Быстрое многократное нажатие стрелки влево больше не склеивает несколько
  escape-последовательностей в одну и не воспринимает их как `Esc`. Это
  устраняло неожиданный выход из главного меню.
- Неизвестные escape-последовательности теперь игнорируются, а не закрывают
  текущий экран.
- Стрелка влево в поле ввода больше не отменяет ввод.

### Тесты

- 445 assertions в 9 файлах.

## [1.3.0] - 2026-10-31

### Добавлено

- Режим «сначала настройки»: восемь сгруппированных страниц (диск, система,
  сборка, ядро, пользователи, службы, графика, проверка) собирают все
  параметры до начала установки.
- Итоговое подтверждение на странице проверки: после него установка идёт
  непрерывно, без вопросов между этапами (`GI_UNATTENDED=1`).
- Фокусируемая нижняя панель действий `<Back>`, `<Next>`, `<Save>` (F2),
  `<Help>` (F1), `<Exit>` (F10); переход с последнего пункта на панель и
  обратно стрелками.
- Стандартные окна выбора `ui_choice`: `[ ]`/`[*]` для нескольких вариантов и
  `( )`/`(*)` для одного; `Space` отмечает пункт.
- Модальные подтверждения `ui_modal_confirm` для стирания диска, уничтожения
  данных при ручном форматировании и старта установки.
- Явный выбор ядра: бинарное `gentoo-kernel-bin`, скомпилированное
  `gentoo-kernel` или ручное `gentoo-sources` + `make menuconfig`. На новой
  установке метод не выбирается по умолчанию.
- Явный выбор обычного пользователя: создание аккаунта, имя и пароль
  запрашиваются на странице пользователей; без согласия аккаунт не создаётся.
- Пароли root и пользователя хранятся только в памяти процесса и очищаются
  после применения.
- Тесты для `ui_choice`, `ui_choice_marker`, `ui_modal_confirm`, `ui_page_run`,
  unattended-режима и явных решений о ядре и пользователе.

### Изменено

- `CFG_KERNEL_MODE` по умолчанию пуст; `config_validate` требует явного выбора.
- `CFG_CREATE_USER` по умолчанию `no`, `CFG_USERNAME` пуст.
- Обычные этапы установки больше не останавливаются на `ui_pause`; сообщения и
  вступления этапов в unattended-режиме не ждут клавишу.
- `ui_failure_choice` в unattended-режиме сразу завершает установку с записью
  ошибки в журнал.
- `--yes` пропускает предупреждение и подтверждение стирания диска, но не
  отменяет запрос паролей.
- В окнах выбора ответ меняется только пробелом; `Enter` переводит фокус на
  панель действий и не может случайно изменить выбор.
- `T` разворачивает `\n` в строках без аргументов, поэтому многострочные
  английские сообщения отображаются корректно.
- Документация, пример конфигурации и счётчики тестов обновлены для 1.3.0.

### Исправлено

- `F10` на странице настроек возвращает код выхода, а не «назад».
- Окно завершения установки остаётся на экране и в автоматическом режиме,
  чтобы были видны инструкции по перезагрузке.
- Ручное форматирование разделов больше не блокирует автоматическую установку
  ожиданием ввода.
- `system_root_password` и `system_create_user` используют пароли, собранные
  мастером, и не спрашивают их повторно без необходимости.

### Тесты

- 404 assertions в 9 файлах.

## [1.2.0] - 2026-10-26

### Добавлено

- Английский интерфейс по умолчанию и необязательный русский перевод
  (`lib/lang/ru.tsv`). При первом запуске установщик предлагает выбрать язык;
  выбор сохраняется в новом ключе `UI_LANGUAGE`.
- Параметр `--lang en|ru` и пункт смены языка в главном меню.
- Для русского интерфейса подбирается `ru_RU.UTF-8`; при отсутствии локаль
  создаётся через `localedef`, иначе используется `C.UTF-8`.
- Нижняя панель действий `<Select>`, `<Exit>`, `<Save>`, `<Help>` на всех
  экранах, как на макете интерфейса.
- Компактная сводка текущей конфигурации: режим загрузки, диск и размер,
  файловые системы, swap и `/home`, Stage3, ядро, графика, прогресс, язык и
  локаль.
- Горячие клавиши: `F1` — справка, `F2`/`Ctrl-S` — сохранение, `F10` — выход
  с текущего экрана.
- Надёжное определение размера блочных устройств: `blockdev --getsize64`,
  `lsblk -bndo SIZE` и `/sys/block`/`/sys/class/block` с проверкой результата.
- Регрессионные тесты для virtio-дисков KVM/QEMU и для локализации, панели
  действий, сводки и сохранения языка.

### Изменено

- Все пользовательские строки переведены на английский как исходный язык.
  Статические подписи переводятся автоматически в `ui_*`, динамические
  сообщения используют `T 'формат %s'`, чтобы сохранять порядок подстановок.
- Русский текст вынесен в TSV-каталог; отсутствующие записи откатываются к
  английскому.
- `UI_LANGUAGE` добавлен в `CONFIG_KEYS`, пример конфигурации и `Makefile`
  (каталог `lib/lang/` устанавливается вместе с библиотеками).
- Документация обновлена для версии 1.2.0.

### Исправлено

- KVM/QEMU с virtio-диском `/dev/vda` больше не определяется как диск размером
  `0 MiB`; установка не блокируется на этом диске.
- Проверка размера отбрасывает пустые, нулевые и подозрительно малые значения
  вместо продолжения с нулевым размером.
- Исправлена строка сообщения о недопустимых символах в командной строке ядра.

### Тесты

- 355 assertions в 9 файлах, включая `test_i18n.sh`, проверки панели действий,
  декодирования F1/F2/F10/Ctrl-S, сводки и отсутствия паролей в конфигурации.

## [1.1.0] - 2026-10-25

### Добавлено

- Необязательное графическое окружение: XFCE + LightDM, GNOME + GDM или
  `DESKTOP="none"` для консольной установки.
- Новый ключ `DESKTOP` с валидацией и настройкой в мастере.
- Этап `desktop` после загрузчика и перед финализацией. При отказе от графики
  этап сразу отмечается завершённым и не требует сети.
- Установка Xorg, драйверов ввода, XFCE/GNOME и соответствующего
  дисплей-менеджера; для OpenRC включаются `dbus`, `elogind` и
  `display-manager`, для systemd — unit менеджера и `graphical.target`.
- Автоматический выбор профиля Portage: XFCE → `desktop`, GNOME → `gnome`;
  явные `kde` и `hardened` сохраняются.
- Для OpenRC-графики в `USE` автоматически добавляется `elogind`, чтобы
  LightDM/GDM собирались и с явным профилем `hardened`.
- Добавление пользователя в группы `plugdev`, `input`, `render`, `video`,
  `audio`, если они существуют.
- Unit-тесты для пакетов, дисплей-менеджеров, служб, проверки установки и
  сетевого требования; всего 288 assertions в 8 файлах.
- Документация по этапу графики, профилям, службам и проверке в VM.

### Изменено

- `STATE_STEPS` и общий счётчик этапов: теперь 9 этапов.
- Preflight считает сеть обязательной, пока выбранный этап графики не завершён.
- Мастер предупреждает, если `DESKTOP` изменён после Portage, и если
  `VIDEO_CARDS` не заданы.

### Безопасность

- Пароли по-прежнему не входят в конфигурацию, состояние и журналы; установка
  графики не добавляет секретов в файлы.

## [1.0.0] - 2026-10-25

Первый публичный релиз.

### Добавлено

- Консольный TUI-установщик на Bash 4.4+ без `dialog`/`whiptail`.
- UEFI + GPT с ESP в `/efi` и BIOS + MBR с `/boot`; загрузчик GRUB.
- Автоматическая разметка по схемам Gentoo AMD64 Handbook и ручное назначение
  существующих разделов.
- XFS, ext4, Btrfs, FAT32 и swap; необязательные отдельные swap и `/home`.
- Stage3 `openrc`, `systemd`, `desktop-openrc`, `desktop-systemd`.
- Загрузка `latest-stage3`, докачка, проверка SHA256 и GPG-подписи.
- Portage: `make.conf`, профили, `CPU_FLAGS_X86`, CFLAGS, USE, `VIDEO_CARDS`,
  `MAKEOPTS`, необязательное обновление `@world`.
- Ядро `gentoo-kernel-bin`, `gentoo-kernel` и `gentoo-sources` с `menuconfig`;
  `installkernel` + `dracut`, firmware и микрокод.
- Настройка hostname, timezone, locale, keymap, fstab, root-пароля и
  пользователя.
- Службы: dhcpcd/NetworkManager, OpenSSH, cronie, chrony, sysklogd/rsyslog,
  sudo и gentoolkit.
- Установка GRUB для UEFI и BIOS с проверкой `grub.cfg` и `root=`.
- Возобновление установки по файлу состояния, сброс состояния, повтор
  неудачных команд.
- Журналы команд с правами `0600`; пароли не сохраняются в конфигурацию и
  журналы.
- Пример конфигурации `conf/installer.conf.example` со всеми ключами.
- Unit-тесты (230 assertions), ShellCheck-проверки, CI и release-сборка.
- Документация: README, Handbook mapping, архитектура, тестирование,
  конфигурация, безопасность.

### Безопасность

- Stage3 не устанавливается без SHA256 или GPG-подписи.
- Конфигурация не исполняется как shell; ключи проверяются по whitelist.
- Kernel cmdline и GRUB defaults защищены от инъекций.
- Destructive-операции требуют `ERASE`, если не указан `--yes`.
- Preflight проверяет окружение до изменения диска.

### Известные ограничения

- Только amd64 и только GRUB.
- Нет LUKS, LVM, RAID, swap-файлов, Btrfs subvolumes и Secure Boot.
- Нет автоматического dual boot; `os-prober` отключён.
- Все разделы установки должны быть на одном диске.
- Автоматический интеграционный тест с реальной разметкой и загрузкой
  отсутствует; перед физической установкой требуется проверка в VM.
