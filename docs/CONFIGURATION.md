# Конфигурация

## Формат файла

Конфигурация — обычный текстовый файл, а не shell-скрипт. Он не выполняется
через `source`, поэтому подстановки команд и переменных не работают.

```text
# Комментарий.
SCHEMA="1"

BOOT_MODE="uefi"          # комментарий после значения тоже допустим
ROOT_FS="xfs"
DISK=""
```

Правила:

- каждая строка — `KEY="value"`; ключ состоит из заглавных латинских букв,
  цифр и `_`;
- значение всегда в двойных кавычках, даже если это число;
- после закрывающей кавычки разрешены пробелы и комментарий `# ...`;
- пустые строки и строки, начинающиеся с `#` (в том числе с отступом),
  игнорируются;
- `\"` и `\\` внутри значения читаются как `"` и `\`;
- `#` внутри кавычек — часть значения, а не комментарий;
- неизвестные ключи, строки без кавычек и текст после значения (кроме
  комментария) отклоняются;
- `SCHEMA` должна быть равна `"1"`.

`config_save` всегда записывает все ключи, экранирует кавычки и обратные слэши,
создаёт файл атомарно и выставляет права `0600`. Паролей в файле нет.

## Расположение и приоритет

По умолчанию:

```text
/var/lib/gentoo-installer/install.conf   конфигурация
/var/lib/gentoo-installer/state          завершённые этапы
/var/lib/gentoo-installer/logs/          журналы
/var/lib/gentoo-installer/downloads/     stage3 и sidecar-файлы
/var/lib/gentoo-installer/gnupg/         временное хранилище ключей
```

Порядок применения значений:

1. Встроенные значения `config_defaults`.
2. Файл, загруженный через `config_load` (автоматически или `--config`).
3. Производные поля `config_derived`.
4. Изменения в мастере; каждое изменение сразу сохраняется.
5. `config_validate` перед стартом установки.

Если указан `--config FILE`, относительный путь приводится к абсолютному.
Файл должен существовать. `--resume` требует существующий файл конфигурации:
без него установщик не знает, какие разделы и UUID использовать.

Пример со всеми ключами и комментариями:
[`conf/installer.conf.example`](../conf/installer.conf.example).

## Ключи

### Схема, загрузка и диск

| Ключ | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `SCHEMA` | `1` | `1` | Версия формата конфигурации. |
| `BOOT_MODE` | `uefi`, `bios` | по режиму live-среды | Схема загрузки и таблица разделов. |
| `DISK_MODE` | `auto`, `manual` | `auto` | Создавать разделы или использовать существующие. |
| `DISK` | путь к блочному устройству | пусто | Целевой диск, например `/dev/nvme0n1`. |
| `ROOT_FS` | `xfs`, `ext4`, `btrfs` | `xfs` | Файловая система root. |
| `HOME_FS` | `xfs`, `ext4`, `btrfs` | `xfs` | ФС отдельного `/home`. |
| `SWAP_MODE` | `auto`, `none`, `custom` | `auto` | Автоматический размер, без swap или свой. |
| `SWAP_MIB` | целое > 0 | `0` | Размер swap; используется только при `custom`. |
| `HOME_MODE` | `no`, `separate` | `no` | Отдельный раздел `/home`. |
| `HOME_MIB` | целое > 0 | `0` | Размер `/home`; нужен при `separate` в auto-режиме. |
| `BOOT_FS` | `xfs`, `ext4`, `btrfs` | `xfs` | ФС `/boot` в BIOS-режиме. |

### Ручные разделы

| Ключ | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `PART_ESP` | путь к разделу | пусто | ESP для UEFI. |
| `PART_BOOT` | путь к разделу | пусто | `/boot` для BIOS. |
| `PART_SWAP` | путь к разделу | пусто | Раздел swap; пусто — без swap. |
| `PART_ROOT` | путь к разделу | пусто | Корневой раздел, обязателен. |
| `PART_HOME` | путь к разделу | пусто | Отдельный `/home`; пусто — без него. |
| `FORMAT_ESP` | `yes`, `no` | `yes` | Форматировать ESP. |
| `FORMAT_BOOT` | `yes`, `no` | `yes` | Форматировать `/boot`. |
| `FORMAT_SWAP` | `yes`, `no` | `yes` | Выполнять `mkswap`. |
| `FORMAT_ROOT` | `yes`, `no` | `yes` | Форматировать root. |
| `FORMAT_HOME` | `yes`, `no` | `yes` | Форматировать `/home`; при `HOME_MODE=no` сбрасывается в `no`. |
| `UUID_ESP` | UUID | пусто | Заполняется установщиком. |
| `UUID_BOOT` | UUID | пусто | Заполняется установщиком. |
| `UUID_SWAP` | UUID | пусто | Заполняется установщиком. |
| `UUID_ROOT` | UUID | пусто | Заполняется установщиком. |
| `UUID_HOME` | UUID | пусто | Заполняется установщиком. |

Все `PART_*` должны указывать на разделы одного диска. Для UEFI таблица должна
быть GPT, для BIOS — MBR. Если `FORMAT_*="no"`, установщик проверяет тип
существующей ФС. UUID не следует задавать вручную: они снимаются после
форматирования.

### Stage3 и Portage

| Ключ | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `STAGE_FLAVOR` | `openrc`, `systemd`, `desktop-openrc`, `desktop-systemd` | `openrc` | Вариант stage3. |
| `MIRROR` | HTTP(S)-URL | `https://distfiles.gentoo.org` | Базовый URL зеркала distfiles. |
| `STAGE_URL` | HTTP(S)-URL или пусто | пусто | Прямой URL stage3 вместо latest-stage3. |
| `PROFILE` | `stage`, `desktop`, `gnome`, `kde`, `hardened` | `stage` | Профиль Portage. |
| `CPU_FLAGS` | `yes`, `no` | `yes` | Определять `CPU_FLAGS_X86` через `cpuid2cpuflags`. |
| `UPDATE_WORLD` | `yes`, `no` | `no` | Выполнять `emerge --update --deep --newuse @world`. |
| `MAKE_JOBS` | `auto` или целое 1–256 | `auto` | Число задач `make`. |
| `CFLAGS` | строка без кавычек и переводов строк | `-march=native -O2 -pipe` | Флаги компилятора. |
| `VIDEO_CARDS` | токены через пробел или пусто | пусто | Драйверы GPU для Portage. |
| `USE_EXTRA` | USE-токены через пробел или пусто | пусто | Дополнительные USE-флаги. |

При `STAGE_FLAVOR=desktop-*` профиль автоматически становится `desktop`, если
в файле указан `PROFILE="stage"`. Явно выбранные `gnome`, `kde` или `hardened`
не перезаписываются.

### Ядро и загрузчик

| Ключ | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `KERNEL_MODE` | `bin`, `dist`, `manual` | `bin` | Способ установки ядра. |
| `FIRMWARE` | `yes`, `no` | `yes` | Установить `sys-kernel/linux-firmware`. |
| `MICROCODE` | `auto`, `none`, `intel`, `amd` | `auto` | Микрокод CPU. |
| `KERNEL_CMDLINE` | строка без `"`, `$`, `` ` ``, `\`, CR/LF | `quiet` | Дополнительные параметры ядра. |
| `BOOTLOADER` | `grub` | `grub` | Загрузчик; других значений нет. |

`KERNEL_CMDLINE` не должен содержать `root=`: установщик удаляет его из
пользовательского значения, а `root=UUID=...` добавляет сам. Опасные для
`/etc/default/grub` символы запрещены.

### Система

| Ключ | Допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `HOSTNAME` | DNS-совместимое имя | `gentoo` | Имя хоста. |
| `TIMEZONE` | зона IANA, например `Europe/Moscow` | `UTC` | Часовой пояс. |
| `LOCALE` | UTF-8 локаль | `en_US.UTF-8` | Системная локаль. |
| `KEYMAP` | имя keymap | `us` | Раскладка консоли. |
| `HWCLOCK` | `UTC`, `local` | `UTC` | Хранение времени в RTC. |
| `NETWORK` | `dhcpcd`, `networkmanager`, `none` | `dhcpcd` | Сетевой стек установленной системы. |
| `SSH` | `yes`, `no` | `no` | Установить и включить OpenSSH. |
| `CRON` | `yes`, `no` | `yes` | Установить и включить cronie. |
| `CHRONY` | `yes`, `no` | `yes` | Установить и включить chronyd. |
| `SYSLOG` | `yes`, `no` | `yes` | Установить sysklogd (OpenRC) или rsyslog (systemd). |
| `SUDO` | `yes`, `no` | `yes` | Установить sudo и правило для `wheel`. |
| `USERNAME` | имя пользователя | `gentoo` | Обычный пользователь. |
| `CREATE_USER` | `yes`, `no` | `yes` | Создавать пользователя. |

Пароли root и пользователя не являются ключами конфигурации. Они запрашиваются
дважды на этапе «Система» и передаются в `chpasswd` через stdin.

## Производные поля

`config_derived` не принимает пользовательских ключей, но меняет `CFG_*` перед
сохранением и проверкой:

- `CFG_INIT` = `systemd`, если вариант stage3 содержит `systemd`, иначе
  `openrc`;
- профиль `desktop` подставляется для desktop-stage3 только при
  `PROFILE="stage"`;
- при `SWAP_MODE != custom` размер `SWAP_MIB` обнуляется;
- при `HOME_MODE=no` очищаются `PART_HOME`, `UUID_HOME`, а `FORMAT_HOME`
  становится `no`;
- при `SWAP_MODE=none` очищаются `PART_SWAP`, `UUID_SWAP`, а `FORMAT_SWAP`
  становится `no`;
- при UEFI очищается `PART_BOOT`/`UUID_BOOT`, при BIOS —
  `PART_ESP`/`UUID_ESP`;
- UUID очищается, если соответствующий `PART_*` пуст.

При `SWAP_MODE=auto` уже найденный `PART_SWAP` и его UUID сохраняются: это
позволяет продолжить установку, не создавая swap заново. Размер при этом
пересчитывается при новом планировании.

## Примеры

### UEFI, OpenRC, бинарное ядро

```text
SCHEMA="1"
BOOT_MODE="uefi"
DISK_MODE="auto"
DISK="/dev/nvme0n1"
ROOT_FS="xfs"
HOME_MODE="no"
SWAP_MODE="auto"
STAGE_FLAVOR="openrc"
PROFILE="stage"
KERNEL_MODE="bin"
BOOTLOADER="grub"
HOSTNAME="gentoo"
TIMEZONE="Europe/Moscow"
LOCALE="ru_RU.UTF-8"
KEYMAP="ru"
NETWORK="dhcpcd"
USERNAME="witch"
CREATE_USER="yes"
```

### BIOS, systemd, сборка distribution-ядра

```text
SCHEMA="1"
BOOT_MODE="bios"
BOOT_FS="ext4"
DISK_MODE="auto"
DISK="/dev/sda"
ROOT_FS="ext4"
HOME_MODE="separate"
HOME_MIB="40960"
SWAP_MODE="custom"
SWAP_MIB="4096"
STAGE_FLAVOR="systemd"
PROFILE="desktop"
KERNEL_MODE="dist"
FIRMWARE="yes"
MICROCODE="auto"
NETWORK="networkmanager"
```

### Ручная схема с сохранением ESP и `/home`

```text
SCHEMA="1"
BOOT_MODE="uefi"
DISK_MODE="manual"
DISK="/dev/sda"
PART_ESP="/dev/sda1"
PART_ROOT="/dev/sda3"
PART_HOME="/dev/sda4"
FORMAT_ESP="no"
FORMAT_ROOT="yes"
FORMAT_HOME="no"
ROOT_FS="btrfs"
HOME_FS="btrfs"
SWAP_MODE="none"
HOME_MODE="separate"
```

Перед запуском такой конфигурации разделы уже должны существовать, ESP должен
содержать FAT32, а `/home` — поддерживаемую ФС.

## Проверка и типичные ошибки

`config_validate` проверяет не только типы, но и окружение, а `preflight`
дополнительно проверяет утилиты и доступность сети:

- UEFI/BIOS в конфигурации должен совпадать с режимом загрузки live-среды;
- автоматический режим требует существующий блочный диск не меньше 16 GiB;
- BIOS + MBR запрещён для дисков > 2 TiB;
- ручные разделы должны существовать, быть уникальными и на одном диске;
- preflight требует `mkfs.xfs`/`mkfs.btrfs`, если выбраны эти ФС;
- hostname, timezone, locale, keymap, CFLAGS, USE, VIDEO_CARDS и kernel cmdline
  проходят собственные валидаторы;
- `MAKE_JOBS` — `auto` или целое 1–256.

Ошибки показываются списком в TUI и дублируются в журнал. После исправления
запустите проверку конфигурации повторно.

## Состояние и повторный запуск

Файл состояния содержит только отметки `step=done`, например:

```text
disk=done
stage3=done
```

Конфигурация и состояние разделены. Сброс состояния в главном меню удаляет
только отметки этапов и размонтирует целевую систему; конфигурация и данные на
диске остаются. При следующем запуске установка начнётся с разметки.

Если этап уже завершён, мастер не позволяет менять его ключевые параметры
(диск, stage3, ядро, системные службы). Чтобы применить другие параметры,
сбросьте состояние. Загрузка другого файла конфигурации не отменяет отметки
уже завершённых этапов — используйте это осознанно.

`--resume`:

1. требует существующий `install.conf`;
2. загружает состояние;
3. если `finalize=done`, выводит сообщение и завершается с кодом 0;
4. иначе проверяет окружение, монтирует разделы по UUID и продолжает с первого
   незавершённого этапа.

Незавершённый этап выполняется заново. Команды, которые уже были успешно
выполнены внутри этапа, могут повториться; большинство операций Portage и GRUB
идемпотентны, но разметка и форматирование не являются таковыми — поэтому этап
`disk` отмечается завершённым только после успешного монтирования.
