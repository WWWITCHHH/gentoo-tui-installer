# Gentoo TUI Installer

Консольный установщик Gentoo Linux для запуска из **Gentoo Minimal Installation CD**.
Интерфейс по умолчанию английский; при первом запуске можно выбрать русский.
Код и комментарии — на английском. Установщик проводит пользователя по этапам
официального [Gentoo AMD64 Handbook](https://wiki.gentoo.org/wiki/Handbook:AMD64)
и не требует `dialog`, `whiptail` или других внешних TUI-библиотек.

> **Важно.** Установщик создаёт и удаляет разделы и файловые системы. Перед
> запуском сделайте резервную копию данных. Автоматические тесты не затрагивают
> реальные диски, поэтому сначала проверьте установку в виртуальной машине.

## Возможности

- Собственный ANSI/Unicode TUI: страницы настроек, окна выбора и модальные
  подтверждения. Нижняя панель действий `<Back>`, `<Next>`, `<Save>` (F2),
  `<Help>` (F1) и `<Exit>` (F10) доступна с клавиатуры и компактная сводка
  конфигурации показывается на каждом экране.
- Режим «сначала настройки»: восемь сгруппированных страниц (диск, система,
  сборка, ядро, пользователи, службы, графика, проверка) собирают все параметры
  до начала работы. После одного итогового подтверждения установка идёт
  непрерывно, без вопросов между этапами.
- Английский интерфейс по умолчанию и необязательный русский перевод. Язык
  выбирается при первом запуске, параметром `--lang` или в главном меню. Для
  русского интерфейса подбирается или генерируется UTF-8 locale.
- UEFI + GPT (ESP в `/efi`) и BIOS + MBR (`/boot`), загрузчик GRUB.
- Автоматическая разметка по схеме Handbook или ручное назначение существующих
  разделов.
- XFS, ext4 и Btrfs для root, `/home` и `/boot`; FAT32 для ESP; swap.
- Система инициализации: OpenRC или systemd. Stage3 `desktop-*` выбирается
  автоматически, когда выбрано графическое окружение.
- Проверка Stage3 по SHA256 и GPG-подписи ключом релизов Gentoo.
- Portage: зеркало, профиль, `make.conf`, `CPU_FLAGS_X86`, `MAKEOPTS`, CFLAGS,
  USE и необязательное обновление `@world`. `VIDEO_CARDS` определяется по GPU
  автоматически; при необходимости выбирается из списка или задаётся вручную.
- Ядро: явный выбор между `gentoo-kernel-bin`, `gentoo-kernel` или
  `gentoo-sources` + `make menuconfig`. Бинарное ядро не выбирается по
  умолчанию; ручная конфигурация остаётся интерактивной. Initramfs через
  `installkernel`/`dracut`.
- Настройка системы: hostname, timezone, locale, keymap, fstab, пароль root.
  Создание обычного пользователя — отдельный явный вопрос: имя, пароль и группы
  задаются на странице пользователей; без согласия аккаунт не создаётся.
- Службы: dhcpcd или NetworkManager, OpenSSH, cronie, chrony, sysklogd/rsyslog.
  `sudo` для группы `wheel` настраивается на странице пользователей.
- Опциональное графическое окружение: XFCE + LightDM или GNOME + GDM, либо
  установка без графики. Xorg и драйверы устанавливаются вместе с окружением.
- Сохранение состояния и продолжение установки после перезапуска; повторный
  запуск спрашивает только недостающие пароли и подтверждение стирания диска.
- Надёжное определение размера диска через `blockdev`, `lsblk` и sysfs, включая
  virtio-диски `/dev/vda` в KVM/QEMU.
- Подробные журналы команд; пароли хранятся только в памяти процесса и не
  записываются в конфигурацию, состояние или журналы.
- Модальные подтверждения для стирания диска и старта установки; при
  противоречивых сочетаниях настроек показывается отдельное предупреждение с
  явным выбором «Продолжить всё равно». `--yes` пропускает только предупреждение
  и подтверждение диска.

## Ограничения версии 1.4.0

- Только **amd64/x86_64**.
- Только **GRUB**. Другие загрузчики не поддерживаются.
- Из графических окружений поддерживаются только **XFCE** и **GNOME**;
  дисплей-менеджеры фиксированы: LightDM для XFCE и GDM для GNOME.
- Графическое окружение ставится после загрузчика и перед завершением. Если
  сменить `DESKTOP` после этапа Portage, профиль Portage уже не пересобирается:
  для его применения нужно сбросить состояние и установить систему заново.
- Нет LUKS, LVM, RAID, swap-файлов и автоматического dual boot.
- Secure Boot не настраивается; при включённом Secure Boot неподписанный GRUB
  может не загрузиться.
- Btrfs создаётся без subvolumes и сжатия.
- Отдельные разделы для `/var`, `/usr` и других точек монтирования не
  создаются.
- Нет автоматического разбиения на несколько дисков: все разделы одной
  установки должны быть на одном диске.

## Требования

- Gentoo Minimal Installation CD, загруженный в нужном режиме (UEFI или BIOS).
- root-доступ в live-окружении.
- Bash 4.4 или новее; в актуальном Minimal CD используется Bash 5.x.
- Сеть до выбранного зеркала distfiles.
- Утилиты, входящие в Minimal CD: `parted`, `blkid`, `blockdev`, `lsblk`,
  `findmnt`, `mkfs.vfat`, `mkfs.ext4`, `mkswap`, `tar`, `xz`, `curl`, `gpg`
  (опционально).
- Для русского интерфейса — `localedef` (входит в glibc), если локаль
  `ru_RU.UTF-8` ещё не установлена в live-среде.
- Для XFS и Btrfs — `xfsprogs` и `btrfs-progs`; установщик проверяет их наличие
  и отказывается продолжать, если выбранная ФС не поддерживается.

Проверка окружения выполняется до изменения диска: архитектура, UEFI/BIOS,
дата, сеть, обязательные команды, целевой диск и Secure Boot.

## Быстрый старт

1. Загрузитесь с Gentoo Minimal Installation CD и настройте сеть и время:

   ```bash
   net-setup eth0        # или dhcpcd eth0
   chronyd -q            # если время сбито
   ```

2. Скопируйте каталог проекта или release-архив в live-систему и запустите
   установщик от root:

   ```bash
   tar -xpf gentoo-tui-installer-1.4.0.tar.gz
   cd gentoo-tui-installer-1.4.0
   ./gentoo-installer
   ```

   Установка в live-систему не обязательна. При желании можно выполнить
   `make install` (по умолчанию в `/usr/local`), но live-система эфемерна.

3. При первом запуске выберите язык интерфейса: English (по умолчанию) или
   Русский. Затем выберите «Настроить и установить» и последовательно заполните
   восемь страниц: загрузка и диск, система, Stage3 и сборка, ядро,
   пользователи, службы, графика, проверка. На странице проверки подтвердите
   установку один раз — дальше установщик работает без вопросов. Пароли
   вводятся на странице пользователей и остаются только в памяти.

4. После завершения извлеките установочный носитель и перезагрузитесь:

   ```bash
   reboot
   ```

Если установка прервалась, запустите установщик снова или используйте:

```bash
./gentoo-installer --resume
```

Завершённые этапы будут пропущены, целевые разделы будут проверены и
смонтированы по сохранённым UUID.

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `-c, --config FILE` | Использовать указанный файл конфигурации. |
| `--lang en\|ru` | Язык интерфейса: английский (по умолчанию) или русский. |
| `-r, --resume` | Сразу продолжить установку с сохранённого состояния. |
| `-y, --yes` | Не показывать предупреждение и не требовать подтверждения стирания диска. Пароли и остальные интерактивные вопросы остаются. |
| `--debug` | Дублировать сообщения журнала в stderr. |
| `-h, --help` | Показать справку. |
| `-V, --version` | Показать версию и `git describe`, если доступен Git. |

`--yes` не отключает проверку окружения и не отменяет запрос паролей. Не
используйте его в сценариях, где подтверждение уничтожения данных обязательно.
При обычном запуске стирание диска и старт установки всегда требуют модального
подтверждения.

## Язык интерфейса и панель действий

Английский — исходный и используемый по умолчанию язык. При первом запуске без
сохранённой конфигурации установщик показывает выбор `English` / `Русский`;
решение сохраняется в `UI_LANGUAGE` и используется при следующих запусках.
Изменить язык можно в главном меню или параметром `--lang en|ru`.

Для русского интерфейса установщик ищет `ru_RU.UTF-8`, при необходимости
создаёт её через `localedef` и выставляет UTF-8 окружение. Это влияет только на
интерфейс установщика; системная локаль целевой системы задаётся отдельно
ключом `LOCALE`. Если русскую локаль создать не удалось, используется
`C.UTF-8`, а кириллица всё равно отображается корректно.

Внизу каждого экрана отображается панель действий и подсказка:

```text
  ↑/↓ — move · Enter — edit · Esc — back
  <Back>  <Next>  <Save> F2  <Help> F1  <Exit> F10
```

| Клавиша | Действие |
|---|---|
| `↑`/`↓` | Перемещение по пунктам; `↓` на последнем пункте переводит на панель действий, `↑` с панели возвращает к пунктам. |
| `←`/`→` | Выбор кнопки на панели действий. На содержимом страницы эти клавиши игнорируются. |
| `Пробел` | Отметить пункт в окне выбора: `[ ]`/`[*]` для нескольких вариантов, `( )`/`(*)` для одного. |
| `Enter` | Изменить поле, перейти к панели действий или нажать кнопку. Выбор варианта в окне выбора выполняется только пробелом, поэтому Enter не меняет ответ случайно. |
| `Esc` | Вернуться на предыдущую страницу. |
| `F1` | Справка по клавишам. |
| `F2`, `Ctrl-S` | Сохранить конфигурацию. |
| `F10` | Выйти с текущей страницы (на первой странице — подтверждение выхода из настройки). |

Над панелью выводится краткая сводка: режим загрузки, диск и его размер,
файловые системы, swap и `/home`, вариант Stage3, метод установки ядра,
графическое окружение, прогресс этапов, язык и целевая локаль. Сводка
обновляется при каждом изменении конфигурации.

## Страницы настройки

| № | Страница | Что настраивается |
|---:|---|---|
| 1 | Загрузка и диск | UEFI + GPT или BIOS + MBR, автоматическая разметка или готовые разделы, целевой диск, файловые системы, swap и `/home`. |
| 2 | Система | Hostname, timezone, locale, keymap, аппаратные часы и язык установщика. |
| 3 | Stage3 и сборка | Система инициализации OpenRC или systemd, зеркало, прямой URL, производный профиль Portage, `CPU_FLAGS_X86`, `@world`, `MAKEOPTS`, CFLAGS, USE. |
| 4 | Ядро и загрузчик | Явный выбор бинарного, скомпилированного или ручного ядра, linux-firmware, микрокод, cmdline, GRUB. |
| 5 | Пользователи | Создавать ли обычного пользователя, имя, пароли root и пользователя, sudo. |
| 6 | Службы | Сеть, SSH, cron, chrony, syslog. |
| 7 | Графика | Без графики, XFCE + LightDM или GNOME + GDM; `VIDEO_CARDS` показывается только при выбранной графике и определяется автоматически. |
| 8 | Проверка и установка | Полная сводка, валидация, проверка противоречий, пароли при необходимости, итоговое подтверждение стирания диска и старта. |

## Этапы установки

| № | Этап | Что делает |
|---:|---|---|
| 0 | Проверка | Проверяет live-окружение, сеть, инструменты и диск. |
| 1 | Диск | Создаёт GPT/MBR и разделы либо использует ручную схему; форматирует, собирает UUID и монтирует. |
| 2 | Stage3 | Загружает `latest-stage3`, проверяет SHA256 и GPG, распаковывает архив. |
| 3 | Portage | Копирует `resolv.conf`, пишет `make.conf`, синхронизирует дерево, выбирает профиль, определяет CPU-флаги. |
| 4 | Ядро | Устанавливает прошивки, микрокод, `installkernel`/`dracut` и ядро выбранным способом. |
| 5 | Система | Настраивает hostname, время, локаль, keymap, fstab, root-пароль и пользователя. |
| 6 | Службы | Устанавливает и включает сеть, SSH, cron, chrony, syslog, sudo, gentoolkit. |
| 7 | Загрузчик | Устанавливает GRUB в ESP или MBR, генерирует и проверяет `grub.cfg`. |
| 8 | Графика | Устанавливает Xorg и XFCE + LightDM или GNOME + GDM; при `DESKTOP=none` пропускается. |
| 9 | Завершение | Выполняет `depclean`, удаляет временные файлы, размонтирует разделы. |

Подробное соответствие главам Handbook и отличия описаны в
[docs/HANDBOOK.md](docs/HANDBOOK.md).

## Конфигурация и состояние

- Конфигурация: `/var/lib/gentoo-installer/install.conf`
- Состояние: `/var/lib/gentoo-installer/state`
- Журнал: `/var/lib/gentoo-installer/logs/install.log`
- Журналы отдельных команд: `/var/lib/gentoo-installer/logs/NN-step.log`
- Загрузки и ключи: `/var/lib/gentoo-installer/downloads`,
  `/var/lib/gentoo-installer/gnupg`

Каталог имеет права `0700`, конфигурация, состояние и журналы — `0600`.
Пароли запрашиваются интерактивно и не сохраняются. Язык интерфейса хранится в
ключе `UI_LANGUAGE` (`en` или `ru`). Полное описание ключей, формата файла и
примеры приведены в [docs/CONFIGURATION.md](docs/CONFIGURATION.md) и
[conf/installer.conf.example](conf/installer.conf.example).

## Разработка и проверка

```bash
make check          # синтаксис, ShellCheck и unit-тесты
make test           # только unit-тесты
make lint           # только ShellCheck
make dist           # архив и SHA256 для тега текущей версии
```

`make check` не требует root и не трогает блочные устройства. Тесты используют
временные каталоги и подменяют пути через переменные `GI_*`.
